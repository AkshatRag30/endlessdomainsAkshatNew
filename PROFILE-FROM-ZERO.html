Profile, from absolute zero

A complete walkthrough of the Profile and Settings page (/profile) from the frontend side: every file, every data type, every hook, every backend call, and how a click turns into a saved row. Written so a beginner can follow it and come out able to change any part of it.

The hotel analogy, frontend editionThe page is the building, the composites are the rooms guests see, the hooks are the staff who fetch things, the helpers are the rule books staff consult, and core is the one phone line to head office (the backend). Guests never phone head office themselves.

One honest caveat up front: in Profile, some composites call hooks themselves (for example ProfileTabPanel calls useProfileDraft). The project's newer rule says only the page should do that. It is a known, listed exception; section 17 explains it.

2. Words you need

view model
The shape the UI wants (for example ProfileDetails with fullName). It is deliberately different from the shape the backend sends (Profile['result'] with name). A mapper converts one into the other.
RTK Query
The data fetching part of Redux Toolkit. You describe an endpoint once (getUserProfile) and get a hook (useGetUserProfileQuery()) that fetches, caches and shares the result between every component that calls it.
query vs mutation
A query reads (GET) and is cached. A mutation changes something (POST, PUT, PATCH, DELETE) and is not cached; its hook returns a trigger function: const [setProfile] = useSetProfileMutation().
.unwrap()
RTK mutation triggers return a special promise that never rejects. .unwrap() turns it into a normal promise that rejects on error, so try/catch works.
cache tag
A label (like 'profile'). A query that provides a tag is refetched automatically when a mutation invalidates it.
QueryResult<T>
The project's small standard result shape: { data?, isLoading, isError, refetch }. Every Profile hook returns it, real or sample, so components never care which.
draft
An editable copy of saved data. You type into the draft; Save sends the differences; Discard copies the saved data back.
dirty
"The draft differs from what is saved." Used to enable Save and to warn before leaving.
optimistic update
Show the change immediately, save in the background, and roll back if the save fails. Used by the notification switches.
debounce
Wait for a pause (400 ms) before acting, so typing a username fires one request, not one per key.
type guard
A function whose return type is value is X; after it returns true, TypeScript treats the value as X.
shallow routing
router.replace(url, undefined, { shallow: true }) changes the URL without re running the page's data fetching.
render prop
Passing a function as a prop, which the child calls with some values. SettingsRow's control can be a function that receives the ids to label a switch with.
roving tabindex
Keyboard pattern for tabs: only the active tab has tabIndex=0; arrow keys move between tabs.
barrel
An index.ts that re exports many components so you can import them from one path.
useSyncExternalStore
A React hook to read a value stored outside React (a module variable) and re render when it changes. Powers the sample data store.
nonce
A one time random string from the backend. The wallet signs it to prove ownership without a password.
minor units
Money stored as an integer of the smallest unit. USDT has 6 decimals, so 4250000000 means 4,250 USDT.

Discriminated union, explained. Every member of SignInMethod has a kind field with a different literal value. When code checks if (method.kind === 'wallet'), TypeScript knows method.address exists inside that branch, and that method.email does not. It is how one list can hold three slightly different shapes safely.

Why two families of types?The backend shape changes when the backend changes; the UI shape changes when the design changes. Keeping them apart, with one mapper between them (mapUser.ts), means a backend rename touches one function instead of twenty components. It also lets sample data and real data share the UI type, so components cannot tell them apart.

5. How it talks to the backend

Profile reaches the backend through three different doors. This is historical, not a design goal: the original endpoints went into RTK Query, the backend developer later added his own fetch wrapper for the new profile APIs, and wallet linking reused the old shared helpers. Knowing which door a call uses tells you how its errors, caching and auth behave.

PieceMeaning

5.2 Door 2: the profile service (fetch wrapper)

The newer profile APIs (added on the backend on 26 Oct) are called through plain async functions in one file. Its heart is a private request function:

src/core/services/profile-settings.service.ts 
interface Envelope<T> {
  message?: string | string[]
  result: T
}

async function request<T>(method: 'GET' | 'POST' | 'PATCH' | 'PUT' | 'DELETE', path: string, options: { body?: unknown; form?: FormData } = {}): Promise<T> {
  const token = getCookieValue(Cookie_Key.ACCESS_TOKEN)
  const headers: Record<string, string> = {}
  if (token) headers.Authorization = `Bearer ${token}`

  let body: BodyInit | undefined
  if (options.form) {
    body = options.form
  } else if (options.body !== undefined) {
    headers['Content-Type'] = 'application/json'
    body = JSON.stringify(options.body)
  }

  const response = await fetch(`${baseUrl}${path}`, { method, headers, body })
  const text = await response.text()
  const json = text ? JSON.parse(text) : undefined
  if (!response.ok) {
    const message = Array.isArray(json?.message) ? json.message.join(', ') : json?.message
    throw Object.assign(new Error(message || `Request failed (${response.status})`), { statusCode: response.status, body: json })
  }
  return json as T
}
LineMeaning
Envelope<T>The backend wraps every answer as { message, result }. A generic interface: Envelope<{ available: boolean }> means "an envelope whose result is { available: boolean }".
request<T>(method, path, options = {})One function for every verb. T is what the caller expects back. The method is a union, so 'GTE' would not compile.
Record<string, string>"An object with string keys and string values." Headers start empty.
Bearer tokenSame idea as Door 1: read the cookie, add the header.
options.form branchFor the avatar upload: a FormData body. No Content-Type is set on purpose; the browser adds multipart/form-data with the right boundary itself.
options.body branchFor JSON: set the header and stringify.
response.text() then JSON.parseReading text first copes with empty bodies (a 204 has none), where response.json() would throw.
if (!response.ok)fetch does not throw on 400 or 500; only on network failure. So the code checks ok (status 200 to 299) itself.
Array.isArray(json?.message)NestJS validation errors arrive as an array of messages; join them into one string.
Object.assign(new Error(...), { statusCode, body })Make a real Error (so .message works in toasts) and attach the status and raw body for callers that need them.

The exported functions are all short wrappers. Two deserve a look:

getAccountSummary is a mapper inside the service: the volume arrives as a string of USDT minor units, so Number(...) / 1_000_000 turns "4250000000" into 4250 (the underscores in 1_000_000 are just digit separators). A missing join date becomes ''. signOutOtherSessions shows the backend's token rotation from the frontend side: it returns a brand new token pair, which replaces this browser's cookies so this device stays signed in while others are cut off.

What Door 2 does not haveNo cache and no sharing: two components calling getAccountSummary would send two requests. useAccountSummary works around that with its own inFlight promise (section 13). No automatic token refresh either: if the access token has expired, these calls simply fail with 401.

Interlude: helpers vs hooks

Before the tabs, the one distinction that makes the rest of this guide easy: what is a helper, what is a hook, and how do you know which one you are writing? Profile has 4 helper files and 15 hook files (16 hooks: useConnectedWallets.ts also exports useWalletCount), and every one of them is discussed below.

The main difference, in one sentence each

HelperA plain function. Give it input, it gives back output, the same output every time for the same input. It has no memory, does not know React exists, and never talks to the network. It is a calculator.
HookA function whose name starts with use and that runs inside a React component while it renders. It can remember things between renders (state), run code after render (effects), call other hooks, and fetch data. Its answer can change over time, and when it does, the component re renders. It is a staff member with a notebook and a phone.

The same job is usually split between them. Here is the Profile tab's details, side by side:

// HELPER: src/helpers/profile/mapUser.ts. Pure: object in, object out.
export function mapUserToDetails(user: User): ProfileDetails {
  return { fullName: user.name ?? '', email: user.email ?? '', /* ... */ }
}

// HOOK: src/hooks/profile/useProfileDetails.ts. Fetches, remembers, re renders, and USES the helper.
export function useProfileDetails() {
  const query = useGetUserProfileQuery()                 // another hook: fetch + cache
  const user = query.data?.result
  const data = useMemo(() => (user ? mapUserToDetails(user) : undefined), [user])   // helper called inside
  // ... save, upload, resend
  return { data, isLoading: query.isLoading, /* ... */ }
}

The hook does everything that involves time (waiting for the network, remembering, updating the screen). The helper does everything that is just logic (renaming fields, applying rules). That division is the whole idea.

The rules of hooks, and why helpers do not have them

React tracks a component's hooks by their order: the first useState call is slot 1, the second is slot 2, on every render. So hooks have two rules: call them only at the top level of a component or another hook (never inside an if, a loop, or a callback), and only from React functions. Break the order and React hands slot 2's state to the wrong variable.

// WRONG: the hook runs on some renders and not others, so every hook after it shifts slot
if (activeTab === 'wallets') {
  const wallets = useConnectedWallets()
}

// RIGHT: call it every render, decide what to show afterwards
const wallets = useConnectedWallets()
if (activeTab === 'wallets') { /* use wallets.data */ }

Helpers have no such rules because React does not track them: call validateProfile(draft) inside an if, a loop, an event handler, anywhere.

Ask one question: does this code need React state, an effect, another hook, or the network?

3src/helpers/profile/base58.ts: turning bytes into text

src/helpers/profile/base58.ts 
const BASE58_ALPHABET = '123456789ABCDEFGHJKLMNPQRSTUVWXYZabcdefghijkmnopqrstuvwxyz'

export function base58Encode(input: Uint8Array): string {
  let zeros = 0
  while (zeros < input.length && input[zeros] === 0) zeros++

  const digits: number[] = []            // the number in base 58, least significant digit first
  for (const byte of input) {
    let carry = byte
    for (let j = 0; j < digits.length; j++) {
      carry += digits[j] << 8             // shift everything so far up by one byte (× 256) and add the new byte
      digits[j] = carry % 58               // keep what fits in this base 58 digit
      carry = (carry / 58) | 0             // carry the rest to the next digit (| 0 = whole number)
    }
    while (carry > 0) {                  // the number grew: add new digits at the top
      digits.push(carry % 58)
      carry = (carry / 58) | 0
    }
  }

  let out = '1'.repeat(zeros)            // each leading zero byte is written as '1'
  for (let i = digits.length - 1; i >= 0; i--) out += BASE58_ALPHABET[digits[i]]
  return out
}

A Solana signature is 64 raw bytes, and the backend wants it as text. Base58 is like writing a number in base 10, except with 58 symbols, chosen so that easily confused characters (0, O, I, l) never appear. The algorithm treats all the bytes as one huge number and converts it to base 58 with schoolbook long division, one byte at a time.

Worked example, bytes [0, 0, 1]:

  1. Count leading zero bytes: zeros = 2.
  2. Byte 0: digits is empty, carry = 0, nothing added. Same for the second 0.
  3. Byte 1: carry = 1; the inner loop does nothing (no digits yet); the while pushes 1 % 58 = 1. Now digits = [1].
  4. Output: '11' for the two zeros, then BASE58_ALPHABET[1] which is '2'. Result "112".

<< 8 is a bit shift, multiplying by 256 (one byte). (x / 58) | 0 is a fast way to drop the decimals. It is written without BigInt because the project's TypeScript target does not support it. A perfect helper: pure arithmetic, no imports at all.

The URL is the source of truth for the tab (so /profile?tab=wallets can be bookmarked and shared). Missing or invalid ?tab= means Profile. But there is a subtlety the comments explain: Next.js updates the URL inside a React transition, which React may delay while other updates are busy, so a tab read only from the URL sometimes did not switch on click. The fix is a two source design:

  1. requestedTab holds the tab you just clicked, immediately.
  2. activeTab = requestedTab ?? urlTab: the click wins until the URL catches up. ?? means "use the right side only if the left is null or undefined".
  3. The first effect clears requestedTab once the URL shows the same tab, so the URL leads again.
  4. The second effect clears it on a real (non shallow) navigation or on Back/Forward (popstate), so a link from the sidebar always wins over a click whose URL never landed.
  5. Both effects return a cleanup that removes the listeners. Without it, every re mount would add another listener and they would pile up.

useWalletCount() reads the cached user (Door 1) and returns the number of wallets for the Wallets tab badge, or null until loaded so no wrong number flashes.

8.1.1 useProfileAction: a tiny reusable pattern

src/hooks/profile/useProfileAction.ts 
export function useProfileAction<Args extends unknown[], R>(action: (...args: Args) => Promise<R>) {
  const [isSaving, setIsSaving] = useState(false)
  const actionRef = useRef(action)
  actionRef.current = action

  const run = useCallback(async (...args: Args) => {
    setIsSaving(true)
    try {
      return await actionRef.current(...args)
    } finally {
      setIsSaving(false)
    }
  }, [])

  return { run, isSaving }
}

Given any async function, it returns run (same arguments, same result) plus an isSaving flag. finally clears the flag whether it succeeded or threw; errors still reach the caller, who shows its own toast. The generics Args extends unknown[] and R make run keep the exact argument and return types of the function you passed. The ref trick makes run stable forever (empty dependency list) while always calling the latest action, which would otherwise capture stale values like an old user. Eight hooks reuse it.

    return shown
  }, [allErrors, submitted, touched, usernameStatus])

Three pieces of state drive everything:

StateMeaning
draftThe editable copy. Filled once from saved by the effect. Later reloads of saved do not overwrite it (!draft), so a background refetch never wipes what you are typing.
touchedWhich fields you have left (blurred). Errors appear only after you leave a field, not while you type the first letter.
submittedAfter pressing Save once, every error shows.

And everything else is derived with useMemo rather than stored, which avoids keeping copies in sync:

  1. usernameToCheck: ask the backend only about a username that changed and already passes the format rules (!validateProfileField(...) is true when there is no error). Otherwise pass '' to keep the checker idle.
  2. allErrors: every rule failure right now, plus "taken" from the backend.
  3. errors: what to show: all of them after submit, otherwise only touched fields, except "taken" which shows while typing.
  4. changes: only the fields that differ (section 8.4). isDirty is simply "there is at least one".
  const setField = useCallback(<K extends keyof ProfileDetails>(field: K, value: ProfileDetails[K]) => {
    setDraft((current) => (current ? { ...current, [field]: value } : current))
  }, [])

  const blur = useCallback((field: ProfileField) => setTouched((current) => ({ ...current, [field]: true })), [])

  const submit = useCallback(async () => {
    if (!draft || !saved) return null
    setSubmitted(true)
    const firstInvalid = (Object.keys(allErrors) as ProfileField[])[0]
    if (firstInvalid) return { invalidField: firstInvalid }
    if (!isDirty) return null
    const next = await details.save(changes)
    setDraft(next)
    setTouched({})
    setSubmitted(false)
    return { saved: next }
  }, [draft, saved, allErrors, isDirty, details, changes])

  const discard = useCallback(() => {
    setDraft(saved ?? null)
    setTouched({})
    setSubmitted(false)
  }, [saved])
FunctionExplained
setField<K extends keyof ProfileDetails>A generic function: the type of value depends on field. setField('phone', 'abc') will not compile because ProfileDetails['phone'] is an object. [field]: value is a computed property name. The updater form setDraft(current => ...) always starts from the latest draft.
blurMarks a field touched.
submitReturns one of three results, a small union of objects: { invalidField } (focus it), { saved } (success), or null (nothing to do). On success the draft becomes exactly what the backend stored, and touched and submitted reset.

8.3.1 useUsernameAvailability: debounced live check

src/hooks/profile/useUsernameAvailability.ts 
export function useUsernameAvailability(username: string): UsernameAvailability {
  const [state, setState] = useState<{ username: string; status: UsernameAvailability }>({ username: '', status: 'idle' })

  useEffect(() => {
    if (!username) return
    let cancelled = false
    setState({ username, status: 'checking' })
    const timer = setTimeout(() => {
      checkUsernameAvailable(username)
        .then((available) => { if (!cancelled) setState({ username, status: available ? 'available' : 'taken' }) })
        .catch((err) => { if (cancelled) return; console.error(...); setState({ username, status: 'idle' }) })
    }, DEBOUNCE_MS)
    return () => {
      cancelled = true
      clearTimeout(timer)
    }
  }, [username])

  return username && state.username === username ? state.status : 'idle'
}

Each keystroke changes username, which re runs the effect. The cleanup of the previous run clears its timer, so only a 400 ms pause actually sends a request: that is the debounce. The cancelled flag stops a slow old answer from overwriting a newer one. Storing username next to status and comparing on return is a second guard: never report an older name's answer for the name being typed now. A failed check returns to 'idle' rather than blocking you; Save checks again anyway.

8.4 Validation: validation.ts

export const PROFILE_LIMITS = { fullName: 60, username: [3, 30] as const, telegram: [5, 32] as const, bio: 160, location: 80, website: 200 }

export type ProfileField = 'fullName' | 'username' | 'email' | 'phone' | 'telegram' | 'bio' | 'location' | 'website'
export type ProfileErrors = Partial<Record<ProfileField, string>>

export const TELEGRAM_RE = /^(?=.{5,32}$)(?!.*__)(?!_)[A-Za-z0-9_]+(?<!_)$/

export function validateProfileField(field: ProfileField, draft: ProfileDetails): string | undefined {
  switch (field) {
    case 'username': {
      const v = draft.username
      const [min, max] = PROFILE_LIMITS.username
      if (!v) return undefined
      if (!/^[a-z0-9_]+$/.test(v)) return 'Use lowercase letters, numbers and underscores only.'
      if (v.length < min || v.length > max) return `Use ${min} to ${max} characters.`
      return undefined
    }
    case 'website': {
      const v = draft.website.trim()
      if (!v) return undefined
      if (v.length > PROFILE_LIMITS.website) return 'That link is too long.'
      try {
        const url = new URL(v)
        if (url.protocol !== 'https:' || !url.hostname.includes('.')) return 'Use a full https:// link.'
      } catch {
        return 'Use a full https:// link.'
      }
      return undefined
    }
    // ... fullName, email, phone, telegram, bio, location
  }
}
PieceMeaning
as constMakes [3, 30] a fixed pair (a readonly tuple) instead of number[], so const [min, max] = ... is typed exactly.
Partial<Record<ProfileField, string>>An object that may have any of the field names as keys, each with a message. Empty object = no errors.
Every field optionalif (!v) return undefined: wallet only accounts start with no name or email, so empty is allowed; a filled value must be valid.
switch with block scoped case { }The braces let each case declare its own const v.
Website via new URL()The browser's URL parser throws on garbage; the catch turns that into a message. Then require https: and a dot in the host.
Telegram regex(?=.{5,32}$) length 5 to 32; (?!.*__) no double underscore; (?!_) not starting with _; (?<!_)$ not ending with _. Lookaheads and lookbehinds check without consuming characters.

And the diff that decides what Save sends:

export function profileChanges(saved: ProfileDetails, draft: ProfileDetails): Partial<ProfileDetails> {
  const clean: ProfileDetails = {
    ...draft,
    fullName: draft.fullName.trim(),
    email: draft.email.trim(),
    telegram: normalizeTelegram(draft.telegram),   // drops a leading @
    location: draft.location.trim(),
    website: draft.website.trim(),
    phone: draft.phone && draft.phone.number ? draft.phone : null,
  }
  const patch: Partial<ProfileDetails> = {}
  for (const key of Object.keys(clean) as (keyof ProfileDetails)[]) {
    if (JSON.stringify(clean[key]) !== JSON.stringify(saved[key])) (patch as Record<string, unknown>)[key] = clean[key]
  }
  return patch
}

10.3 Signing with Solana: solana-signing.ts and base58.ts

src/helpers/profile/solana-signing.ts 
export interface SolanaSigner {
  signMessage: (message: Uint8Array) => Promise<Uint8Array | { signature: Uint8Array }>
}

export async function signSolanaMessage(signer: SolanaSigner | undefined, message: string): Promise<string> {
  if (!signer?.signMessage) throw new Error('This wallet does not support message signing')
  const raw = await signer.signMessage(new TextEncoder().encode(message))
  const bytes = raw instanceof Uint8Array ? raw : raw.signature
  return base58Encode(bytes)
}

Solana wallets sign bytes, not text, so TextEncoder turns the message into UTF 8 bytes (Uint8Array). Different wallets return either the raw bytes or an object with a signature field; the union return type and the instanceof check handle both. The backend expects the signature in base58 (Bitcoin's alphabet without the confusable 0 O I l), so base58Encode converts it: it treats the bytes as one big number and repeatedly divides by 58, keeping remainders as digits, and writes each leading zero byte as a '1'. It is written without BigInt because the project's TypeScript target does not allow it.

    if (Object.keys(switchPatch).length > 0) {
      setSwitches(await updateNotificationSwitches(switchPatch))
    }
  })

  const data = switches ? { ...switches, channels } : undefined
  return { data, isLoading, isError, refetch, update, isSaving, isMock: false }

export const getProfileMock = <K extends keyof ProfileMockState>(key: K): ProfileMockState[K] => state[key]

export function setProfileMock<K extends keyof ProfileMockState>(key: K, next: ProfileMockState[K]): ProfileMockState[K] {

  listeners.forEach((listener) => listener())
  return next
}

export function useProfileMock<K extends keyof ProfileMockState>(key: K): ProfileMockState[K] {
  const read = () => state[key]
  return useSyncExternalStore(subscribe, read, read)
}

export const mockSaveDelay = (ms = 350) => new Promise<void>((resolve) => setTimeout(resolve, ms))

This is a tiny global store in 30 lines, the same idea Redux is built on:

  1. state is a module variable: it lives as long as the page, so it survives tab switches; a reload resets it.
  2. setProfileMock never mutates: it builds a new object and then notifies every listener. React compares snapshots by reference, so mutating in place would go unnoticed.
  3. useSyncExternalStore(subscribe, read, read) is React's official way to read outside state: React calls subscribe with its own listener, and re renders the component whenever read() returns something new. The third argument is the value used during server rendering.
  4. The generic <K extends keyof ProfileMockState> ties the key to the value type: setProfileMock('sessions', x) requires x to be ActiveSession[].
  5. mockSaveDelay fakes network time so "Saving…" states are visible in review.

17. Quirks in the real code

Spotting these is a sign you understand the page. None is urgent; talk to the team before changing them.

Three doors to the backendRTK Query, the profile service's fetch wrapper, and the old api.service.
