Sign in with your domain: a login SDK for mini games

A login that lets a player sign in to any mini game with a domain they own (for example akshat.og), proven with their wallet. Endless Domains becomes the login provider, like "Sign in with Google"; games add it with a small SDK and trust the result on their own servers. This page is the complete plan: how it works, every part to build, the APIs, the security rules, and the phases with tasks, tests and exit gates.

1. Summary

The idea. Many players already own domains through Endless Domains. A domain is a readable, unique, portable name. We let mini games use it as the player's login name: the player connects a wallet, signs a free message to prove the wallet is theirs, picks one of the domains that wallet owns, and the game receives a signed, verifiable identity such as { name: "akshat.og", wallet: "0x8FD5…Be4D0" }.

The approach. Endless Domains runs a standard OpenID Connect (OIDC) login service, using Sign In With Ethereum (EIP 4361) as the way the player proves who they are. On top sits a tiny JavaScript SDK (EndlessLogin.signIn()) and a server helper for games to verify the result. Because it's a standard, games can also use any existing OIDC library instead of ours.

Why it's good for us. Every game that adds it shows our brand at login, gives domain owners a reason to use their names, and turns players without a domain into buyers ("Get your own name").

2. Goals and non goals

Goals

1) A player signs in to a game with a domain they own, in under 30 seconds, with no password and no gas. 2) The game's server can check the login without trusting the browser. 3) Ownership is checked on chain at sign in and again on refresh, so a sold domain stops working. 4) Any web game can integrate in under an hour. 5) Works with MetaMask, WalletConnect phone wallets and the wallets we already support.

Non goals (first release)

No payments or in game purchases. No on chain game state or achievements. No Solana or non EVM wallets. No smart contract wallets (EIP 1271) at first. No native mobile SDKs (web games first; native can use the OIDC standard directly). No social login fallback (Google, email) in the SDK itself.

3. How it works, step by step

The player's view and what happens behind it. Names in code are defined in the API section.

1

Game

The player clicks "Sign in with your domain". The SDK opens a popup to login.endlessdomains.io/authorize with the game's client_id, its redirect address, a random state and a PKCE code_challenge.

2

Login page

Shows the game's name and logo ("Space Runner wants you to sign in"). The player connects a wallet (AppKit: MetaMask, WalletConnect, Coinbase…). If they're already signed in to Endless Domains in this browser, steps 3 and 4 can be skipped (single sign on).

3

Login service

Hands out a one time nonce. The page builds a Sign In With Ethereum message (shows the site, the wallet, the game, the nonce, an expiry) and the wallet asks the player to sign it. Free, no transaction.

4

Login service

Checks the signature recovers to the wallet, the nonce is unused and unexpired, the message's domain and chain are ours. Marks the nonce used.

5

Login service

Lists the domains this wallet owns (from our discovery tables), then confirms each candidate on chain (owner and expiry). Shows them to the player, with the primary name first.

6

Login page

The player picks a domain and sees a consent screen: "Space Runner will see: your domain name, your wallet address, your avatar". Approve.

7

Login service

Stores the choice, creates a short lived authorization code, and sends the browser back to the game's redirect address with code and state. The popup closes.

8

Game / SDK

Exchanges the code plus the PKCE code_verifier at /token for an ID token (who the player is), an access token and a refresh token.

9

Game server

Verifies the ID token's signature with our public keys (/.well-known/jwks.json), checks aud, iss, exp, and creates its own game session for sub. Shows "Welcome, akshat.og".

10

Later

Every refresh re-checks on chain that the wallet still owns the domain. If it was sold, transferred or expired, the refresh returns the identity without that name (or fails, by the game's choice), so a sold name can't keep being used.

4. Architecture

Game (client)Any web game. Loads @endlessdomains/login, calls signIn(), gets tokens.
Game server (optional)Verifies ID tokens with @endlessdomains/login-verify or any JWT library and our JWKS.
Login pageHosted by us at login.endlessdomains.io: connect, sign, pick, consent. Built with our design system.
Login serviceNew NestJS module in our backend: OIDC endpoints, SIWE, domain checks, tokens, client registry.
  • Where the login service lives: a new module src/components/login-provider/ in the existing backend (NestJS), reusing its database, chain readers, AWS secrets and deploy. A separate service is possible later if load requires it.
  • Where the login page lives: a new small Next.js app or a route group in an existing frontend, served on its own subdomain (login.endlessdomains.io) so its cookies and security headers are separate from the marketplace (decision D4).
  • Where the SDK lives: a new repository endlessdomains-login-sdk publishing two npm packages (browser SDK, server verifier) and a CDN script build.

Base https://login.endlessdomains.io (stage: https://loginstage.endlessdomains.io). OIDC endpoints follow the standard exactly; the /api/… ones are private to our login page.

ThreatRule

12. The SDK

Browser package: @endlessdomains/login

import { EndlessLogin } from '@endlessdomains/login'

const login = new EndlessLogin({
  clientId: 'space-runner',
  redirectUri: 'https://spacerunner.game/auth/callback',
  scope: 'openid profile wallet',     // wallet: include the address
  mode: 'popup',                      // or 'redirect'
  environment: 'production',          // or 'stage'
})

const user = await login.signIn()     // { name, domain, walletAddress, picture, idToken }
login.onChange((user) => render(user))  // sign in, refresh, name lost, sign out
const token = await login.getIdToken()  // fresh, refreshed when needed
await login.signOut()
  • Also: handleRedirectCallback() for redirect mode; signIn({ prompt: 'select_account' }) to switch domain; a ready made button login.renderButton(element, { theme }) using our brand.
  • Builds: ESM and CommonJS for npm, a UMD file on our CDN (<script src="…/endless-login.min.js">) for plain HTML games; TypeScript types; target under 15 KB gzip; no wallet libraries inside (the wallet lives on our login page).
  • Engines: works in any browser game (Phaser, PixiJS, Three.js, plain canvas); Unity WebGL through a small JS bridge example; native apps use the standard OIDC flow (documented, no SDK in phase 1).

Server package: @endlessdomains/login-verify

import { verifyIdToken } from '@endlessdomains/login-verify'

const claims = await verifyIdToken(idToken, { audience: 'space-runner' })
// throws if signature, issuer, audience or expiry is wrong; caches our JWKS
// claims.sub = stable player id for this game; claims.name = display name

Any JWT library works too (jose, PyJWT, Go jwt): it's standard ES256 with our JWKS.

Wallet proof (SIWE) and domain service

5 to 6 days · BE

In plain words: prove the wallet is the player's, then find and confirm the domains it owns.

Tasks

  1. /authorize creates a login transaction (validates client, redirect, PKCE, scope) and redirects to the login page with the transaction id.

Tests

Keeping names honest after sign in

3 days · BE

In plain words: when a domain is sold, transferred or expires, games learn it quickly.

Tasks

  1. Listen to transfer events already seen by our pollers (marketplace poller, Alchemy) for domains with active refresh tokens; mark them for re-check.
  2. On a confirmed loss, revoke the refresh family's domain (next refresh returns domain_status: "lost"), and drop the cached consent choice.
  3. Optional webhook per client (domain.lost, signed with our key) for games that want instant updates.
  4. Daily job: purge expired transactions, codes, nonces; report counts.

Tests

  • Transfer a test domain to another wallet: within one refresh (or one webhook) the old player no longer shows the name; the new owner can sign in with it.

19. Glossary

OIDC
OpenID Connect: the standard "Sign in with…" protocol used by Google, Apple and others.
SIWE
Sign In With Ethereum (EIP 4361): a standard, readable message a wallet signs to prove it owns an address. Free, no transaction.
PKCE
A one time secret the game creates so a stolen login code is useless to anyone else.
ID token
A signed note from us saying who the player is (their domain and a stable id for this game).
JWKS
Our public keys, published so anyone can check our signatures.
Pairwise id
A player id that is different for every game, so games can't track players across each other.
Primary name
The domain a wallet has chosen to be known by (reverse record).
Single sign on
Signing in once to Endless Domains and then entering other games with one click.
