3. The first build (28 Oct)

Before your PDF, bulk listing already worked with one signature per name. This is the base v2 was built on, and all of it is still in use:

  • Select mode on My Domains: a Bulk List button and Quick Action, a banner with the count and Select All (capped at 50), and a Select button on every row and card. Names that can't be listed (already listed, sold, expired) have a disabled Select with the reason.
  • The bulk drawer: the list of picked names (each removable), pricing, duration, the real fee breakdown and "You receive if all sell".
  • Approval, signing and results: the one time marketplace approval, progress while signing, and a results screen for all listed, partly listed and nothing listed.
  • Care for every user: a "Discard this bulk listing?" question before losing typed prices, focus kept inside the drawer, Escape handling, screen reader announcements, and layouts checked at desktop, tablet and phone widths in both light and dark.

4. Reading your requirements first (19 Nov)

Before writing any v2 code I read your PDF line by line, the backend repository (read only) and our branch, and wrote a review page. It found 10 gaps between the PDF and reality. A few examples:

  • Names held across several linked wallets clash with the backend's one seller per batch rule.
  • The Seaport ABI we share with the multi chain work had no cancel function.
  • Listings that were delisted off chain earlier are still valid on the blockchain, so the backend refuses a new, more expensive listing for the same name (CHEAPER_ORDER_STILL_VALID). This later became the "Cancel older listings" feature.
  • Wallets upgraded with EIP 7702 must not be treated as smart contract wallets.

I also wrote a plain words explainer of tickets F1 to F9 and a phase by phase plan, so the work could be followed by anyone on the team.

7. A full code review of my own work (24 Nov)

Since I worked alone, nobody else had reviewed the code, so I did a full review of the whole bulk listing feature before calling it done. It found 0 critical, 5 high, 17 medium and 29 low issues. I wrote every fix in plain words first, then fixed them in steps:

  • Cancel only while it can really cancel. After signing, the drawer shows "Publishing your listing" and hides Cancel, so it can never say "Nothing was listed" while the listing is actually being posted. "Sign each name separately" stops after two identical wallet errors in a row.
  • Reading the backend's answers correctly. Only network trouble, server errors and rate limits offer Try again; a refused batch, a wrong wallet or an expired login go back to the form with a clear message. A broken answer no longer leaves the drawer stuck. Before Try again, the wallet that signed is checked. Posts give up after 45 seconds instead of hanging.
  • Drawer details. Totals and counts include only names that will really be listed; no second paid approval after a Cancel; typed prices are kept when switching pricing (and the seller is asked before they are replaced); the results title matches the result.
  • Project structure. A few files break our team's folder rules (code that talks to the backend sitting in a component folder). The cheap parts were fixed now; the rest is recorded in our layering cleanup plan to be done with the other pages, so this release stays low risk.
  • The high issues that sat in the safeguards were resolved by removing them.

9. Incidents and investigations

24 Nov, stage backend outage. For a short while stage returned errors (500) on both the bulk listing post and the delist record. In one case the cancel had already gone through on the blockchain, but the backend couldn't record it: the row still showed the listing, and pressing Delist again sent a second paid cancel. The backend healed itself a few minutes later from the chain (email sent, row back to List). I ruled out our side (same requests worked before and after) and the timing points to the multi chain migrations landing on stage; I've prepared a question for Guru to confirm. Full write up: incident-24nov-backend-500.html.

  • An expired login showed up as a 401 during testing. Not a bug, but it led to the clearer "login expired" message.
  • Old off chain listings blocking new ones (see Cancel older listings in section 6): found on uat, understood, and solved in the product.
