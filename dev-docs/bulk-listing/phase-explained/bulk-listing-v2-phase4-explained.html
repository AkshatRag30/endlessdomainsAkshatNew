Bulk listing v2 · phase 4 explained

Phase 4 in simple words: the safety nets

Phase 3 made "one signature for all names" work. Phase 4 adds three safety nets for when it can't: a backup way to sign, a clear message for smart contract wallets, and a last moment network check. What each of the 8 changed files does, why, and how to try it. Written 20 Nov 2026; line numbers as of that day.

1. The story in five sentences

  1. Phase 3 made the drawer ask for one signature that covers every name.
  2. That message is big and unusual (orders nested inside pairs), and some wallets can't sign it: hardware wallets like Ledger, some phone wallets, and smart contract wallets like Safe. Mohit sir's F3 says to keep the old "one popup per name" way as a backup.
  3. Phase 4 offers that backup only when the wallet really fails, never when you just cancel.
  4. Smart contract wallets aren't supported yet (Mohit sir's decision 10), so they now get a clear message instead of a confusing failure.
  5. And if you switch your wallet off Polygon while the drawer is open, you now get "switch to Polygon" instead of "something went wrong".

2. Words to know first

WordIn simple words
Bulk signatureThe one signature that covers every name (phase 3).
FallbackThe backup plan: sign each name separately, one popup each, like the October version.
Smart contract walletA wallet that is a program on the blockchain (like Safe, often shared by a team), not a key in your browser. It signs in a completely different way.
Account codeWhat the blockchain stores at an address. A normal wallet has none; a smart contract wallet has its program there. That's how we tell them apart.
EIP 7702A newer feature that lets a normal wallet (even MetaMask) attach extra code. Its code starts with 0xef0100. It still signs like a normal wallet, so we treat it as normal.
Chain / networkWhich blockchain your wallet is on. Listings are on Polygon (chain 137).
Wallet test matrixA table of wallets and whether bulk listing works in each. Mohit sir wants it with the pull request.

3. The three safety nets

A

Backup: "Sign each name separately"

F3

When: you click List, the wallet is asked for the one big signature, and it fails (an error), or it signs but the signature doesn't check out (the wallet read the big message differently).

You see: "Your wallet couldn't sign them all at once. Some wallets, like hardware and some phone wallets, can't sign one big message. You can sign each name separately instead: one popup per name. Nothing has been listed yet." Buttons: Sign each name separately and Back to the form.

If you choose it: "Signing 1 of 8", one popup per name, each name sent on its own. Cancel one and you're asked "Continue with the rest / Stop here". Then the usual result screen.

Never offered when: you cancelled, the wallet is on the wrong network, it's a smart wallet, the wallet isn't linked to your account, or something failed before the wallet was even asked. Signing per name wouldn't help in any of those.

B

Smart contract wallets: a clear "not yet"

F9, decision 10

When: the drawer opens and the connected wallet is a smart contract wallet.

You see: "Smart contract wallets can't bulk list yet. This wallet is a smart contract wallet (like a Safe). For now, bulk listing needs a regular wallet such as MetaMask. Connect a regular wallet to list these names." with a Switch wallet button. List is disabled.

Checked twice: when the drawer opens, and again the moment you click List. If it's only caught at List: "This is a smart contract wallet, which can't bulk list yet. Nothing was listed."

C

Network check at the last moment

Gap from phase 3

When: you opened the drawer on Polygon, then switched your wallet to another network, then clicked List.

Before: the wallet refused and you saw "Something went wrong before signing". With the new backup, it would even have offered "Sign each name separately", which can't help.

Now: "Your wallet is on the wrong network. Switch to Polygon and try again. Nothing was listed." and the wrong network banner with its Switch button.

5. File 1 · the rules · bulkBatch.ts

1

Two small rules

+23 lines
  1. isSmartContractCode(code) · line 94Given an address's code: empty means a normal wallet; starting with 0xef0100 means a normal wallet using EIP 7702; anything else means a smart contract wallet. Example: 0x → normal; 0x6080… → smart; 0xef0100… → normal.
  2. offersPerNameFallback(outcome, lastScreen) · line 106Says yes only if (1) nothing was signed, (2) the last screen was "Sign once for all N names", so the wallet really was asked, and (3) the reason is a wallet error or a signature that didn't check out. Everything else: no.

14. Questions you might have

  1. Why not just offer the backup every time something fails?Because for a cancel, a wrong network or a smart wallet it can't help, and it would mean up to 50 more popups for nothing.
  2. Does the backup cost gas?No. Each name is a free signature, the same as before.
  3. Is the backup as good as the main path?The listings are the same and just as valid. The difference is popups: one per name instead of one in total, and each name is sent separately.
  4. Why does "Should have a queue" appear on my dev server?The dev server's hot reload keeps old state when new hooks are added. Refresh the page; it can't happen on the live site.
  5. Why can't I test with Phantom without my domains in it?A listing must be signed by the address that owns the domain. A different address owns nothing and isn't linked to your account.
  6. Did Guru's test page have these nets?It checks the network before signing (we now do too). It has no backup and no smart wallet check; it's a test tool.
