1. The story in five sentences

  1. Delisting is two steps: the cancel transaction on the blockchain, then telling our backend about it.
  2. On 24 Nov the first step worked and the second failed, so the site still showed the listing.
  3. The toast sounded like success, the row still said Edit price, so Delist was pressed again: a second fee for nothing.
  4. The backend fixed itself minutes later by noticing the cancel on the blockchain.
  5. Now the page remembers the cancel itself, says so clearly, refuses to pay twice, and keeps telling the backend until it listens.

3. The memory

The page keeps a small note in your browser (Local Storage, ed:sent-cancels): which listing, which transaction, when, and whether the backend recorded it. A recorded cancel is remembered for 30 minutes, an unrecorded one for up to a day while it's retried. It's only a helper: the blockchain and the backend are still the truth, and if the browser can't store it, the page simply works as before.

5. Questions you might have

  1. Does this cost anything?No. Telling the backend again is a normal request, not a blockchain transaction.
  2. What if I use another browser?That browser has no note, so it relies on the backend as before; the backend still heals itself from the blockchain.
  3. Can it block a real delist?Only for an order that already has a cancel on its way. Once the note expires (30 minutes after it's recorded), Delist works normally again.
