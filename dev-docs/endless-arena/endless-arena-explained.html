A beginner's guide to one HTML file

Inside Endless Arena

Your senior built a full 3D game in a single file of 667 lines: endless-arena.html. This guide walks through it from the very start, in plain words first and then the real code, so you understand every part, including how it remembers your best score after you close it, and what you could add yourself.

Level 1

One file holds three languages

Every web page is made of three things. The game puts all three in one file, which is why you can open it by double clicking.

PartLanguageIts jobLines in the file
StructureHTMLThe boxes on screen: menu, buttons, score card, the canvas the 3D world is drawn on142 to 236
LooksCSS, inside <style>Colours, fonts, sizes, the pulsing Burst button, the red flash when you get hit11 to 140
BehaviourJavaScript, inside <script>Everything that moves, thinks, scores and saves239 to 664
In plain words

HTML is the skeleton, CSS is the clothes, JavaScript is the brain. About 40 of the 115 KB are just the Endless logo drawing, pasted in three times.

It also borrows three things from the internet, which is why the game needs a connection the first time:

  • Three.js (version r128) from cdnjs: a library that does the hard maths of drawing 3D shapes.
  • qrcode-generator from jsDelivr: turns the website address into the QR code on the result card.
  • Google Fonts: the fonts Unbounded (titles) and Atkinson Hyperlegible (text), chosen for easy reading on small screens.
Level 2

What happens when you open it

A browser reads the file from top to bottom. When it reaches the script at the end, it runs these lines once (line 654 onward):

initGL();        // set up the 3D renderer, lights and the shiny reflections
resize();        // match the canvas to your screen size
makeQR();        // draw the QR code for the result card
refreshMenu();   // fill in "Best run", your identity, today's Daily score
showUI("menu");  // show the menu, hide the game screens
requestAnimationFrame(frame); // start the loop (next level)

Then it wires up the buttons. For example $("goRun").onclick = () => start("run") means "when someone clicks Play, start the Campaign". The little $ is a shortcut the author wrote on line 241 for document.getElementById.

Pressing a mode calls start(). It counts the play, saves your profile (more on that in Level 4), switches the screen to the game view and creates a new game with Arena(mode, identity, guest). Everything about one run lives inside that Arena function, and it is thrown away when the run ends.

Level 3

The game loop: 60 tiny photos a second

A game is a flip book. About 60 times every second the browser calls frame(), which does two things: update the world a tiny bit, then draw it.

Read input→Move you→Spawn enemies→Shoot→Check hits→Draw→Repeat
function frame(now){
  const dt = Math.min(.05, (now - last) / 1000); // seconds since the last photo
  last = now;
  if (game) game.update(dt, now/1000); else idle(now/1000); // play, or wave the menu robot
  R.render(scene, cam);                 // draw the picture
  requestAnimationFrame(frame);         // ask for the next one
}
Why dt matters

dt is "how much time passed". Every speed is multiplied by it, so the robot moves the same distance per second on a fast laptop and a slow phone. The Math.min(.05, …) part caps it, so if your phone freezes for a second the game doesn't jump forward wildly.

Some fun tricks live in update: freeze stops time for a split second when you kill a big enemy (that "hit stop" feeling), and slow runs time at 30% speed for dramatic moments like the boss dying.

Level 4

How it remembers your high score

This is the part you asked about. The game has no server and no account. It uses something every browser has, called localStorage.

In plain words

localStorage is a small notebook that the browser keeps on your computer's disk, one notebook per website. A page can write a line into it, like eplay:arcade = {...}, and read it back later. Because it's on disk, it is still there after you close the tab, close the browser, or restart the computer.

The two helper functions (line 246 and 247)

function load(k, d){             // k = the name, d = the default if nothing is saved
  try {
    const v = localStorage.getItem("eplay:" + k); // read the line
    return v ? JSON.parse(v) : d;              // text back into an object
  } catch(e){ return d; }                     // storage blocked? use the default
}
function save(k, v){
  try { localStorage.setItem("eplay:" + k, JSON.stringify(v)); } // object into text, write it
  catch(e){}
}

Simplified slightly: the real version also keeps a copy in a variable called mem, so the game still works for the current visit if the browser refuses storage.

localStorage can only hold text. That's why the game uses JSON.stringify to turn its profile object into text before saving, and JSON.parse to turn it back when loading.

What exactly is saved

Key in the notebookWhat's insideWhen it's written

A saved profile looks like this:

eplay:arcade = {"plays":12, "ident":"akshat.og", "run":48210, "attack":15300,
                "rush":9020, "daily":{"day":"2026-11-12", "score":22140}}

Example values, not read from your browser.

How a new best is decided (line 644)

if (o.score > (prof[o.mode] || 0)) {  // beat the saved best for this mode?
  prof[o.mode] = o.score;               // replace it
  best = true;                          // show "New best" on the card
}
save("arcade", prof);                   // write the notebook

Daily works a little differently: it keeps the score together with the date. If the saved date isn't today, any score counts as today's best. The date is taken in UTC, so for you in India the Daily resets at 5:30 in the morning.

When your score would disappear

The notebook belongs to one browser on one device
  • Clearing browsing data or "site data" wipes it.
  • Incognito or private windows throw it away when you close them.
  • Another browser, another computer or your phone each have their own empty notebook.
  • For a file opened from your disk, browsers handle the notebook in their own ways. Moving the file to a different folder can start a fresh one.
  • Anyone can open DevTools and type a fake score. It's a personal record, not proof.

See it yourself

  1. Open the game in Chrome, press F12, go to the Application tab, then Local storage on the left. You'll see the eplay: lines.
  2. Or in the Console tab type localStorage.getItem("eplay:arcade") and press Enter.

Level 5

How the 3D world is drawn

Three.js works like a film set. You need four things:

Scene
The stage that holds every object.
Camera
Where we look from. Here it floats above and behind your robot and follows it (line 617). On a tall phone screen it goes higher so you see more.
Lights
A soft sky light, one sun like light, and a coloured point light that travels with you.
Renderer
The camera operator that turns it all into pixels on the <canvas id="gl">.

Nothing is a downloaded model. Every shape is made in code. The mascot robot (buildMascot, line 277) is spheres, cones and rounded boxes stacked together, with the Endless logo painted onto a small disc on its chest. The floor tiles, the skyline around the arena and the glows are drawn with code too.

The speed trick: instancing

Drawing 300 enemies one by one would make a phone stutter. Instead the game uses InstancedMesh: it tells the graphics chip "here is one shape, now draw it 90 times at these 90 positions" in a single go. Every frame it only updates the list of positions and colours. That's why so many things can be on screen at once.

Text that floats over enemies (the addresses, the fake names, your identity) is not 3D. It is normal HTML placed on top of the canvas. The function proj() converts a 3D position into screen pixels so the label sits exactly above the right enemy.

Level 6

The rules of the game, in code

Moving

On a phone, your first finger becomes a joystick wherever you touch (pointerdown), and a second tap dashes. On a laptop the arrow keys or WASD set the direction. The robot can't leave the circle: if it goes past the edge, it is pushed back to the edge.

Shooting by itself

Every frame the game finds the closest enemy within range, turns you toward it, and fires when the fire timer runs out. Powers change the numbers: Rapid Fire shortens the timer, Twin Shot adds bolts, Piercing lets a bolt go through enemies.

Hitting things

There are no physics engines here. A hit is just a distance check: if the distance between a bolt and an enemy is smaller than the enemy's radius, it's a hit.

const dx = e.x - b.x, dz = e.z - b.z;
if (dx*dx + dz*dz < r*r) { /* hit! */ }  // skip the square root, it's faster

Spawning: a money budget

Each round gets a "budget" that grows every second. Each enemy has a price equal to its health. When the budget can afford the next enemy, it buys it and places it in a ring around you, not too close. Later rounds earn budget faster, so more and tougher enemies arrive. Once per round, a big elite enemy appears that always drops an identity.

EnemyHealthWhat it does
Dust1Small and fast, walks at you

Health is multiplied a little each round (hpx: 1, 1.15, 1.3, 1.5).

The boss, The Nameless

It walks toward you, every few seconds fires a ring of 11 bullets, charges in a straight line after a warning, and summons small enemies. At half health it enters phase two: faster, 16 bullets per ring, and it scatters your crew around the arena. Its health is calculated from how strong your build is (estDps() × 30, kept between 240 and 1,700), so the fight takes about the same time for everyone.

Levelling up

Killed enemies drop shards that give experience. When the bar fills, the game pauses and offers three cards. You can hold at most 4 weapon powers and 2 helper powers, each up to level 3. When nothing is left to offer, you get Repair, Reinforce, Full Burst or Bounty instead.

Level 7

The identity idea

This is the part that ties the game to Endless Domains.

  • Enemies are addresses. Each one gets a random label like 0x3f…a91c (hexA()).
  • Some drop a golden token. When you pick it up, the address label scrambles into a name like maya.garden and that little robot joins your crew. Names are made from two lists in the file: first names (maya, theo, zara…) and endings (garden, orbit, harbor…).
  • Your crew helps. Each member circles you, bumps enemies, and adds a damage bonus: 4% each for the first five, 2% each up to ten.
  • Impostors steal. An impostor wears a fake copy of a crew name, with letters swapped for look alike numbers (a becomes 4, o becomes 0, e becomes 3). If it touches you it grabs a crew member and runs. You have 7 seconds to shoot it and bring them back.
  • Your own identity. Type one on the menu and the game makes your robot's colour and ear style from the letters of that name (idLook), so the same name always gives the same robot. It's only text; nothing checks that you own the name.
Level 8

Sound without a single audio file

Every beep, explosion and the music itself is made live by the browser's Web Audio system. An oscillator is a tone generator: you choose the pitch and the wave shape (smooth sine, buzzy square, sharp sawtooth) and how fast it fades.

tone(660, .2, "sine", .09); // pitch 660, lasts 0.2 s, smooth sound, quiet volume

The music (Music, line 360) is a small step sequencer: it plays a drum on every beat and notes from a pattern, and adds layers as rounds go up (hi hats, a second melody, pads). Each round it gets a bit faster and moves to a higher key. When you're on 2 hearts or fewer, a filter muffles it and a heartbeat plays.

Why sound needs a tap first

Browsers don't allow a page to make noise until you interact with it. The game listens for your first tap or key press and starts audio then. For iPhones on silent it also plays a silent looping sound file in the background, because iOS mutes web audio otherwise. That's the odd looking "RIFF WAVE" code on line 323.

Level 10

How you can make it better

It's already well made: smooth on phones, careful with sound, accessible fonts, and it respects "reduce motion". These are ideas you could try, starting with the easiest. Show them to your senior first, since it's their game.

EasyTune the numbers

All the balance lives in a few lists: ROUNDS, ET (enemies), POW (powers), NEED (experience per level). Change one number, reload, feel the difference. The best way to learn how it works.

EasyMake Daily truly the same for everyone

Daily uses a seeded random for which enemies come, but spawn positions, drops and fake names still use Math.random(). Passing the seeded rnd to those too would make every player's Daily identical, which is fairer for comparing scores.

EasyA run history

Save the last 10 runs (date, mode, score, title) in localStorage and show them on the menu. You'd reuse the same save and load helpers from Level 4.

EasyTidy the leftovers

stats.jar, TUNE (gravity, bounce) and MiniKit "jar pieces" come from another game sharing this code and aren't used here. Also !c.stolen || true on line 525 is always true, so that filter does nothing.

MediumShare the result card as an image

Turn the card into a PNG with a canvas and offer it through the phone's share sheet (navigator.share). People share images far more than links.

MediumWork offline

Download Three.js, the QR library and the fonts next to the file instead of loading them from the internet, or add a service worker. Then the game opens without a connection and doesn't break if a CDN is down.

MediumMore settings

Separate music and effects volume, a vibration switch, and a colour blind option (impostors and enemy bullets are both red).

BiggerAn online leaderboard

The localStorage score only lives on one device. A real leaderboard needs a small backend: an endpoint that receives a score and one that lists the top 50. A nice project for your own NestJS practice, and you'd also need some check against fake scores.

BiggerUse a real Endless domain as identity

Connect a wallet and look up the domains it owns, then let the player pick one as their identity. That turns the game's story into the product itself. It needs the team's API and a decision from your senior.

BiggerSplit into files

One file is great for sharing, but hard to work on as it grows. Splitting into modules (renderer, music, enemies, menu) with a small build step would make changes safer.

Glossary

Words used in this guide

localStorage
A small per website notebook the browser keeps on disk. Survives closing the browser.
JSON
A text format for objects, like {"run":48210}. stringify turns an object into JSON text, parse turns it back.
CDN
A fast public server that hosts libraries like Three.js so pages can load them.
Canvas
An HTML element you can draw pixels on. The 3D world lives in one.
dt
Delta time: seconds since the last frame. Keeps speed the same on any device.
requestAnimationFrame
Asks the browser to call your function just before the next screen refresh.
Mesh
A 3D shape plus its material (colour, shininess).
InstancedMesh
One shape drawn many times in one go. The game's performance trick.
Seed
A starting value for a random number generator. Same seed, same "random" numbers.
Oscillator
A tone generator in Web Audio. All the game's sound comes from these.
try / catch
"Try this; if it fails, do that instead of crashing." Used around every storage read and write.
