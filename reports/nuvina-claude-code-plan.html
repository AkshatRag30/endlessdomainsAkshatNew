Building the Nuvina storefront with Claude Code

A plan for building a small, clean Shopify storefront where visitors browse products and order through Shopify checkout. It covers the five documents to write before coding, a light Claude Code setup, and eight phases, each with example prompts, tasks and a clear finish line.

StackNext.js 16, Tailwind v4, Storefront API

Estimate3 to 4 weeks for one developer

AThe approach

The site does four things: show the brand, show the products, hold a cart, and send the visitor to Shopify to pay. Shopify already handles everything else, including payments, COD, taxes, order emails, customer accounts and inventory. So the frontend stays small. It has three folders in src, one file per component, and one folder for all Shopify access.

Connect to a Shopify development store early, in Phase 2, instead of building a mock data layer. With real products, variants and images from the start, you build the product page against real data once, and the "swap mocks for Shopify" step disappears. If store access is delayed, a single lib/shopify/sample.ts file returning the same types keeps you moving.

Each phase follows the same loop with Claude Code:

  1. Plan. Turn on plan mode, point Claude at the phase in docs/PLAN.md, and review what it proposes.
  2. Build. Work one section or component at a time on a branch for the phase.
  3. Check. Run lint and build, and compare the running page with the Figma screenshot for that node.
  4. Review. Run /code-review, fix the findings, read the diff yourself, commit, and tick PLAN.md.
  5. Reset. Run /clear before the next phase.

BFive documents to write before coding

A small project needs a small set of documents. Architecture, conventions and token rules all fit inside CLAUDE.md. Claude Code can draft each document from the blueprint, and you correct it.

You also need store access and a Storefront API token from the store owner, and a decision from the brand team on whether nutrition facts must appear on the product page.

CTemplates

CLAUDE.md

# Nuvina storefront

Small headless Shopify storefront for Nuvina effervescent supplements. Visitors browse
products, add to cart, and pay on Shopify checkout (cart.checkoutUrl). No accounts, no
custom checkout, no global state library.

Stack: Next.js 16 App Router, React 19, Tailwind v4, TypeScript strict, Shopify Storefront API.

## Commands
npm run dev | npm run lint | npm run typecheck | npm run build

## Structure
src/app/            routes; (shop)/layout.tsx holds header, footer, cart drawer
src/components/ui/        generic pieces, no data knowledge (Button, Price, Carousel...)
src/components/layout/    on every page (Header, Footer, AnnouncementBar...)
src/components/sections/  used on two or more pages (MostLoved, Faq, Reels...)
src/components/home/      home page only
src/components/product/   product cards and product page
src/components/cart/      drawer, provider, add to cart button
src/lib/shopify/          the ONLY place that talks to Shopify
src/lib/actions.ts        server actions for the cart and newsletter
src/lib/content.ts        brand copy that is not in Shopify
src/lib/utils.ts          cn, formatMoney, discountPercent

## Rules
1. Pages fetch, components display. Only src/app and src/lib/actions.ts import from lib/shopify.
2. Put a file where it is used. Move home or product files to sections once a second page uses them.
3. Server components by default. Put state in a small sibling file with "use client" (MostLovedTabs.tsx).
4. Colors, fonts and widths come from tokens in globals.css. No hex values or max-w-[...] in components.
5. Product content comes from Shopify; brand copy from lib/content.ts. Never type content into a component.
6. One component per file, PascalCase, named export, props type in the same file.
7. Figma: read one node from docs/FIGMA_MAP.md at a time. Never fetch a whole page frame.
8. Before finishing: run lint, typecheck and build, then tick docs/PLAN.md.

## Never
Expose SHOPIFY_STOREFRONT_TOKEN to the client. Add Redux, a slider library or new top level
folders without asking. Copy placeholder text listed in docs/SCOPE.md.

SHOPIFY_SETUP.md

# Shopify setup

## Products
5 products: hydrate, glow, multi-plus, immune-plus, reset (handles).
Options: "Flavor" (with swatch colors) and "Pack". Set compare at price for sale variants.
Images: first image = card image; add variant images per flavor.

## Product metafields (namespace: custom)
| Key          | Type                   | Used by               |
| tagline      | single_line_text_field | ProductInfo kicker    |
| claims       | list.single_line_text  | badges, attributes    |
| key_benefits | list.single_line_text  | KeyBenefits           |
| ritual       | json                   | RitualTimeline        |  [{ "label": "Day 1", "text": "..." }]
| ingredients  | json                   | Ingredients           |  [{ "name": "...", "benefit": "..." }]
| free_from    | list.single_line_text  | WhatMakesItBetter     |
| faqs         | json                   | Faq                   |  [{ "q": "...", "a": "..." }]
| lab_report   | file_reference         | LabTests              |
Expose each one to the Storefront API (tick "Storefront access" in the definition).

## Collections
best-sellers, new-arrivals, and one per health goal:
hydration, skin-beauty, daily-nutrition, immune-support, digestive-wellness.

## Menus and pages
Menus: main-menu, footer. Pages: shipping, returns, privacy, terms.

## Apps
Headless channel (gives the Storefront token). Judge.me for reviews (writes reviews.rating).

## Env
SHOPIFY_STORE_DOMAIN, SHOPIFY_STOREFRONT_TOKEN, SHOPIFY_API_VERSION=2026-07,
SHOPIFY_WEBHOOK_SECRET, NEXT_PUBLIC_SITE_URL, NEXT_PUBLIC_WHATSAPP_NUMBER

## Webhook
products/update, products/delete, collections/update → POST /api/revalidate

DClaude Code setup

Run /mcp to confirm the Figma server is connected. The three calls you will use are get_design_context for one node's styles, get_screenshot for a visual reference, and get_variable_defs for tokens. Then add one settings file.

// .claude/settings.json
{
  "permissions": {
    "allow": [
      "Bash(npm run lint)", "Bash(npm run lint:fix)", "Bash(npm run typecheck)",
      "Bash(npm run build)", "Bash(npx prettier:*)", "Bash(git status)", "Bash(git diff:*)"
    ],
    "deny": ["Bash(git push:*)", "Read(./.env*)"]
  },
  "hooks": {
    "PostToolUse": [
      { "matcher": "Edit|Write", "hooks": [{ "type": "command", "command": "node .claude/hooks/format.mjs" }] }
    ]
  }
}
// .claude/hooks/format.mjs : runs Prettier on each file Claude edits
import { execFileSync } from 'node:child_process'
let raw = ''
process.stdin.on('data', (c) => (raw += c)).on('end', () => {
  const file = JSON.parse(raw).tool_input?.file_path
  if (file && /\.(tsx?|css|md)$/.test(file)) {
    try { execFileSync('npx', ['prettier', '--write', file], { stdio: 'ignore', shell: true }) } catch {}
  }
})

At this size, custom skills and slash commands are optional. The rules in CLAUDE.md do the same job. Add a skill later if you notice yourself repeating the same instructions.

Staying small. The biggest risk for a small store is gradual sprawl: a hooks folder here, a types folder there, a state library "just for the cart". Every addition should pass the rules in CLAUDE.md. Section 14 of the blueprint lists the signals that mean it is actually time to grow.
