How the page works

Route and layout

pages/profile/index.tsx renders inside MainLayout (site header, sidebar, mobile bottom nav) and MarketplacePageShell. The hero slot holds the title card (ProfileSettingsHeader) and the tab row (ProfileTabs); the main slot holds the active tab panel; the rail slot holds ProfileRail. The tab lives in ?tab=, is validated against PROFILE_TABS, and changes through a shallow router.replace, so switching tabs adds no history entries and never refetches the page. No tab means Profile. Signed out visitors are sent to /login by the existing global ProtectedRoute, since /profile isn't public.

Data flow

Component → hook in src/hooks/profile → profileServices in src/services/profile → mock or api implementation, chosen per area in config.ts. Components never import mock data; an ESLint rule blocks it outside the service folder. Every service throws one error type (ProfileServiceError), so every card shows errors the same way.

Loading, saving and errors

  • useProfileResource keeps each area in a small module cache, so switching tabs doesn't flash skeletons again. Since phase 6 the cache also notifies every mounted hook on the same key (the Wallets tab badge follows the list).
  • While loading, each card shows SettingsCardSkeleton. If a load fails, only that card shows a NoticeBanner with Retry; the rest of the page keeps working.
  • Switches and selects save optimistically: the change shows at once, and if the save fails it rolls back with an error toast.
  • Anything destructive (disconnect, sign out, delete account, discard edits) asks first in ConfirmDrawer, which sits on the existing right side Modal drawer.
  • Cards on sample data show a "Sample data" chip, driven by isMockArea.

Unsaved changes guard (Profile tab)

The Profile form reports whether it has unsaved edits. Switching tabs with edits opens a "Discard unsaved changes?" drawer; leaving for another page asks through the browser confirm (Next's router can't wait for a modal); closing or reloading the tab triggers the browser's own beforeunload prompt.

Removing the sample data later

Set every area in config.ts to 'api', delete src/services/profile/mock/, then drop the mock import and branch in src/services/profile/index.ts. The type check lists anything left over. An area can't be set to 'api' before api/index.ts has an implementation for it; that's a type error.
