How /design-preview/marketplace was actually built

Eleven files, read in order, that walk through every real file behind the page — what each one does, why it's shaped the way it is, and the mistakes that got made and fixed along the way. Not a tour. By the end you should be able to build another page in this same style yourself, without needing this guide open.

01How to use this

Each phase is a real HTML file in this same folder, open them directly in a browser, or click through the sidebar. They build on each other in order — primitives before the composites that use them, the page shell before the sections that sit inside it. If you already know a phase's topic, skip it, the sidebar always shows where you are.

Every phase quotes real code from real files in this project, with the file path labeled on the code block. When you see a path/like/this.tsx chip, that's a real file you can open side by side with the guide. Nothing here is invented for the tutorial — if a snippet looks odd, it's because the real file looks odd, usually for a reason explained right next to it.

How to read the callouts

Teal boxes like this explain why something is built the way it is, the design or engineering reasoning. Amber boxes are a heads up on a convention worth remembering. Red boxes are a real bug that actually happened while building this, kept in because the mistake teaches the mechanism better than getting it right the first time would have.

New to React or CSS at this level?

Every phase after this one assumes you already know what a React hook is, what a flex container does, and why a breakpoint gets wrapped in a Sass mixin instead of written as a raw media query. If any of that isn't second nature yet, start with phase 00, the fundamentals crash course, first — it explains all of it from zero, with small standalone examples, before you meet any of it for real. If you're already comfortable with React and CSS, skip straight to phase 01.

02The 30-second mental model

Everything under /design-preview/marketplace is one Next.js page that assembles a tree of small, single-purpose React components. Every component owns exactly three things: its own markup (a .tsx file), its own styling (a CSS Modules .module.scss file, scoped so its class names can never collide with anyone else's), and nothing else — no component reaches into another component's stylesheet. Data comes from plain TypeScript objects in src/data/marketplace/, typed by interfaces in src/types/marketplace/, so that swapping mock data for a real API later means changing where the data comes from, never how a component renders it.

Three ideas repeat constantly across this codebase once you notice them, and phase 09 covers each in depth once you've seen enough real examples to recognize it:

  • Design tokens over hardcoded values. Colors, spacing, type sizes live as CSS custom properties in one file, tokens.scss, and every component reads var(--space-4) instead of writing 16px.
  • Render both, let CSS decide. When a component looks genuinely different on mobile versus desktop — not just resized, but a different layout — both versions get rendered into the DOM and a media query shows one, hides the other. No JavaScript branching on screen width for layout.
  • Mock data behind a narrow boundary. Every composite that needs data either receives it as a prop or reads one small file in src/data/marketplace/. A real backend replaces that one file's contents, not the component that renders it.

03The folder map

Everything for this page lives under four roots. Skim this once now, it'll make sense of every file path the later phases point at.

src/design-system/ styles/ tokens.scss, _mixins.scss, fonts.scss — phase 01 primitives/ badges, buttons, inputs, charts — phase 02 layouts/header/ the site-wide header — phase 03 composites/marketplace/ shared/ MarketplacePageShell, MobileBottomNav — phase 03 sidebar/ MarketplaceSidebar, MobileDrawerMenu — phase 04 hero/, promoted/ MarketplaceHero, PromotedDomainsSection — phase 05 listings/ ListingCategoryTabs, LiveListingsTable, ListingRow — phase 06 activity/ LiveActivityPanel, LiveActivityTicker — phase 07 analytics/ MarketActivityPanel, MarketMetricCard — phase 07 src/types/marketplace/ one .ts file of interfaces per data domain — phase 08 src/data/marketplace/ one .ts file of mock data per domain — phase 08 src/hooks/marketplace/ useListingFilters.ts — phase 08 pages/design-preview/marketplace.tsx the page itself — assembles everything above
Where the page itself lives

pages/design-preview/marketplace.tsx is short on purpose — maybe 90 lines. It doesn't build UI, it only imports composites and arranges them. Every phase after this one is about what's inside those composites; you'll see the page file itself again in phase 03, once you know what it's assembling.
