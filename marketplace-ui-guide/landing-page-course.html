Endless Domains Landing Page Field Guide

A code audit of every section on the new landing page, a map of how the pieces connect, and a beginner friendly course that rebuilds the whole page by hand, animations included. Every finding here was checked against the actual source in webui/ on the new-landing-page branch (October 2026). Updated after the providers marquee switched to full logo + name artwork.

Part 1 · Is it production grade?

Short answer: the architecture is production grade, but the page is not launch ready until a handful of real bugs and broken links are fixed.

17sections and sub components reviewed (13 section folders, FAQ, page, layout, styles)
0TypeScript errors (tsc --noEmit across the whole project)
36ESLint problems in landing code, mostly auto fixable import sorting
8blocking issues to fix before launch (listed below)

What is genuinely good

  1. Clean structure: one folder per section, a barrel export, and a page that simply stacks sections in order. Easy to read, easy to reorder.
  2. A real design system: CSS custom property tokens for colour, type and spacing, plus SCSS breakpoint mixins used consistently.
  3. Strong TypeScript: strict mode, typed data files, and only three any casts in the whole landing folder.
  4. Careful effect hygiene: almost every observer, timer, interval and animation frame has a matching cleanup.
  5. Thoughtful accessibility in many places: screen reader only headline text, aria-hidden on decoration, a proper tabs pattern with arrow keys, an accessible custom scrollbar slider.
  6. Well chosen techniques: transform only animations, SVG stroke drawing, pure progress functions for scroll stories, and a static page with incremental regeneration for the blog.

What holds it back

  1. A few buttons do nothing, a texture file is missing, and new images are not committed to git.
  2. Two features have real bugs (the counter under reduced motion, and a leak prone controller in the network diagram).
  3. Reduced motion support is inconsistent, and several things move forever with no way to pause.
  4. Desktop and mobile versions of two heavy sections are both mounted, and the hidden one keeps doing scroll work.

Cross cutting issues

Reduced motion is inconsistent Medium

Handled well in TypeWord, the TLD marquee, Roadmap, AdoptionGap, LivingIdentity and the pinned stories. Missing in BoxLoader, StripeAnimation, the search border and placeholder typing, ProvidersMarquee, the partner and payment marquees, the FAQ accordion and the smooth scroll buttons. Fix once with a global rule plus a tiny hook:

// styles: one global safety net
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after { animation-duration: .01ms !important; animation-iteration-count: 1 !important;
    transition-duration: .01ms !important; scroll-behavior: auto !important; }
}
// hooks/useReducedMotion.ts: live, not read once
export function useReducedMotion() {
  const [reduce, setReduce] = useState(false)
  useEffect(() => {
    const mq = matchMedia('(prefers-reduced-motion: reduce)')
    const update = () => setReduce(mq.matches)
    update(); mq.addEventListener('change', update)
    return () => mq.removeEventListener('change', update)
  }, [])
  return reduce
}
Both desktop and mobile versions are always mounted Medium

OwnershipComparison and OnchainIdentityNetwork render a desktop and a mobile component side by side and hide one with CSS at 1180px. That doubles the HTML (duplicate headings), and the hidden desktop controller still listens to scroll on phones, running about 11 and 31 style writes per scroll event. Gate the controllers with matchMedia('(min-width:1180px)') or gsap.matchMedia(), and keep the CSS swap as the server rendered fallback.

Content that is invisible without JavaScript Medium

Roadmap cards, AdoptionGap text, OnchainStats titles and the network diagram all start at opacity: 0 in CSS and only appear when JS sets a data attribute. If JS fails or loads slowly, the content is missing. Put the hidden start state behind a class that JS adds (for example html.js .milestone{opacity:0}) so the default is visible.

Infinite motion with no pause Medium

Four marquees, the How It Works carousel, the hero arcs and the box loaders all move for longer than five seconds. WCAG asks for a way to pause such motion. Options: pause on hover and focus, pause when off screen with an IntersectionObserver, and stop entirely under reduced motion.

Performance budget Info
  1. Three hero background images all load with priority although CSS hides two of them at any given width.
  2. Two centre logo SVGs are about 440 KB each (an embedded PNG plus filters) and are rotated during scroll.
  3. How It Works screenshots total about 2.4 MB and are served unoptimized, so sizes has no effect.
  4. Satoshi and Space Grotesk are loaded asynchronously in _document and then again as render blocking links in MainLayout.
  5. IBM Plex Mono is referenced in four stylesheets but never loaded.
Dead code worth deleting Info
  1. banner-faq/index.legacy.tsx is not imported anywhere.
  2. About 270 unused lines in SearchBar.module.scss (an old copy of the input styles).
  3. The (window as any).__lenis branches: Lenis is not installed and nothing sets it.
  4. Unused gradientId, activePhase, dragging, the missing popRight keyframe and empty SVG filter references.

The page itself is tiny: it imports 15 components from one barrel (composites/landing-page/index.ts) and stacks them. Each section is self contained, owns its data and styles, and takes no props, except the blog teaser.

Folder anatomy (one section)

composites/landing-page/HowItWorksJourney/ ├─ index.ts export { HowItWorksJourney } + default ├─ HowItWorksJourney.tsx the section: state, tabs, layout ├─ HowItWorksJourney.module.scss scoped styles, imports ../../../styles/_mixins.scss ├─ JourneyScreenVisual.tsx small presentational child ├─ journeyData.ts typed content (interfaces + array) └─ useCrossfade.ts a reusable hook for this section

Every section follows this recipe: a section component, an optional data file, optional small children, an optional Animation.ts holding pure maths (for the scroll stories), and a CSS module. That separation, data and maths outside the component, is the single best habit in this codebase.

Styling system

Tokens (runtime CSS variables)

src/design-system/styles/tokens.scss defines everything on :root: colour scales and alpha ramps, text colours, font families, font sizes (--text-h1 … --text-small-12), weights, line heights, the spacing scale --space-1 (4px) to --space-15 (160px), radii, header height and Figma shadows. Some tokens shrink in media queries, so headings resize without touching component code.

Breakpoint mixins (compile time)

Two small inconsistencies: token overrides use inclusive limits (768, 992) while mixins use 767 and 991, and respond-to() does not know about laptop.

Data flow

  1. At build time (and every 60 seconds after, via ISR) getStaticProps asks Ghost for up to 5 featured posts, falling back to the newest 5.
  2. It fetches view counts in one batch and maps posts to a small BlogSummary shape.
  3. The page passes blogPosts to DomainBlogTeaser; if the list is empty the section returns null and disappears.
  4. Everything else is static content inside each section's data file. There is no runtime API call for the landing content itself.
On a failed revalidation the page returns blogPosts: [], which replaces a good cached page with one that has no blog section. Throwing instead keeps the previous good page.

Part 3 · Component deep dives

One card per component: what it does, how it is built, how it moves, and what to fix. Open any card.

IdentityOsHero Minor fixes

What: the first screen. Eyebrow, the headline "Own your [word] forever.", a paragraph, then SearchBar and the "see how it works" button, over rotating arcs and two loading bar ornaments.

Built from: IdentityOsHero.tsx (shell, no props, HERO_WORDS constant), TypeWord, BoxLoader ×2, StripeAnimation, SearchBar, SeeHowItWorksButton.

Nice detail: the animated headline is aria-hidden and a hidden sentence "Own your reputation forever." is what screen readers hear. The first rendered word matches the server, so there is no hydration mismatch.

Fix: change the <h4> tagline to a <p>; remove unused classes (.txt_solid, .strokePath, .animationTrack).

TypeWord Production ready

How it moves: an async while loop inside useEffect. A promise wrapped setTimeout called wait() pauses between letters; the loop deletes with slice, moves to the next word, then types it. Cleanup flips a cancelled flag and clears the pending timer. Reduced motion swaps whole words instead.

BoxLoader Needs work

How it moves: a chained setTimeout state machine fills ten skewed boxes one by one, pauses, then resets. Each box toggles an .active class.

Fix: move the setTimeout out of the setState updater (updaters must be pure); do not mount it at all below 992px instead of hiding it; respect reduced motion; use camelCase SVG attributes (strokeWidth, stopColor); remove the unused gradientId and the missing popRight animation.

StripeAnimation Minor fixes

How it moves: pure SVG, zero JS. Each "blade" is a circle whose stroke-dasharray shows a single 160 unit dash; a SMIL <animateTransform type="rotate"> spins its group around the circle centre every 5 seconds.

Fix: filter="url(#glow)" points at filters that are not defined; SMIL cannot be stopped by a reduced motion media query (switch to a CSS rotation keyframe if you want that).

SearchBar and the Input primitive SearchBar: minor Input: needs work

How it moves: the rainbow border animates a registered custom property --border-angle (via @property) inside a conic-gradient painted on border-box under a white padding-box layer, plus a blurred copy as glow. The TLD pills are a CSS marquee: the list is rendered twice and the track slides translateX(-50%) forever, with a mask-image fade on the edges, a hover pause and a reduced motion stop. The input's placeholder types itself with a timer driven effect.

Fix: delete the ~270 unused lines in SearchBar.module.scss; load one background image per breakpoint instead of three priority images; give the input a visible focus style and at least 16px font on phones; respect reduced motion in the border and placeholder.

SeeHowItWorksButton Minor fixes

A real <button> that calls scrollIntoView({behavior:'smooth'}) on #how-it-works. Styling uses layered box shadows (the last with spread and no blur draws a solid white ring) and a blended texture span.

Fix: compress the 319 KB button-texture.png; add a :focus-visible style; use behavior:'auto' under reduced motion.

IdentityOsProvidersStats + ProvidersMarquee Section ready Marquee: minor

How it is built: a chamfered frame drawn from seven 1px absolutely positioned spans (a diagonal is a bar of width chamfer × √2 rotated 45°), driven by CSS variables that shrink on tablets. Stats switch from a row to a 2×2 grid. The marquee repeats the provider list four times and slides by -25% per loop over 18.3 seconds (about 85px per second).

Logos: all 10 providers show full logo + name artwork from public/new-assets/provider-logos/. Each SVG had its built in padding trimmed by tightening its viewBox. In providersData.ts every provider carries a logo path, a logoAspect (width ÷ height, so next/image gets correct dimensions) and a logoScale optical correction, because a compact two line mark like Binance looks smaller than a bold one line wordmark like Aptos at the same height. CSS sets the height as calc(var(--logo-h) * var(--logo-scale)) with --logo-h 30px on desktop and 24px on tablets and phones. A provider without a logo falls back to the old icon + name text.

Fix: add a reduced motion rule and pause on focus; if the icon fallback is ever used again, normalise #000 to #000000 so the 5c alpha suffix makes a valid colour.

DomainIdentityOS Production ready

Static section: bracketed eyebrow <p>, two tone <h2> with background-clip: text, a connector image and three stat columns with dot capped dividers made from ::before / ::after. On tablets it becomes a 2 column grid and the last stat spans both columns with grid-column: 1 / -1 (selected with :last-of-type because a trailing span breaks :last-child).

OwnershipComparison (+ Mobile) Minor fixes

How it moves: a 400vh section with a 100vh position: sticky stage. A hand written controller computes progress (scrollY − sectionTop) / (sectionHeight − innerHeight) on every scroll. Pure functions in OwnershipComparisonAnimation.ts turn progress into each card's opacity, scale and offset, written with gsap.set; gsap.quickTo pulses the core logo; the last 15% spins the logo down into the next section. A custom scrollbar is a keyboard accessible slider that scrolls the page. No ScrollTrigger is used.

Mobile: a separate static stacked list that imports the same STATES data, so copy cannot drift.

Fix: only start the controller at ≥1180px; re-measure after images and fonts load; give cards a centred, hidden default in CSS so they do not flash stacked before JS; delete the dead Lenis branches.

OnchainIdentityNetwork (+ Mobile) Minor fixes

How it moves: a 550vh sticky stage. On mount it measures the real centres of the core and six nodes with getBoundingClientRect, builds SVG path strings (straight lines and cubic curves), and re-measures on resize, load and document.fonts.ready. Each node has a progress window: the connector draws (strokeDashoffset from length to 0), then the node pops in, then its text settles. Each path has its own userSpaceOnUse gradient so the fade runs from core to node on both sides.

Fix: blocker 7 (compare path strings before setPaths, keep a cancelled flag around the async import, refresh lengths instead of rebuilding); align desktop and mobile copy; remove unused activePhase, dragging and status readout CSS.

DomainOnchainStats Needs work

How it moves: no GSAP. An IntersectionObserver turns ticking on only while visible. A recursive setTimeout with random delays bumps the count. Each digit is an odometer reel: a 1em window over a strip of 0–9 written twice; the strip moves with translateY and a CSS transition, always rolling forward, then snaps back by 10 on transitionend with the transition switched off for one frame. Background "data packets" run CSS keyframes and reschedule on animationend.

Fix: blockers 2, 4 and 5; in DataSlot ignore bubbled events with if (e.target !== e.currentTarget) return.

DomainAdoptionGap Minor fixes

How it moves: an IntersectionObserver latches a triggered flag once; one effect then runs a small timeline of setTimeouts that flip data attributes: the text staggers in, the bar fill scales on X from the left, the numbers count up in steps, and a boundary pulse fires. Reduced motion jumps to the final state.

Fix: render the final numbers on the server (today the HTML says "0M total" and "0%"); correct the stale comments about bar width and timing.

DomainGrowthComparison Needs work

How it moves: bars grow with scaleY from the bottom with a staggered inline delay (and a reversed stagger on exit). The Web3 line is a cubic Bézier path whose length is measured with getTotalLength() and drawn by moving stroke-dashoffset to 0. On desktop with a mouse it activates on hover; on touch it activates once in view.

Fix: blockers 2 and 3; also activate on keyboard focus or on scroll on desktop, otherwise many visitors see empty charts.

DomainLivingIdentity Minor fixes

How it moves: one tick counter, advanced every 2 seconds only while visible, drives everything. The ring rotates by tick × 45° through a CSS variable with a transition; each node counter rotates so its label stays upright. Nodes also sway and breathe with their own keyframe durations so they stay out of phase. Flashes replay by changing a key, which remounts the element and restarts its keyframe. The activity feed places rows in slots from modular arithmetic.

Fix: the row that wraps from top to bottom visibly slides down while fading (move it instantly instead); pause the ambient keyframes off screen.

HowItWorksJourney Needs work

How it moves: five journeys as tabs (correct role="tablist", roving tabIndex, arrow keys). A setInterval advances screens. useCrossfade keeps a displayed copy of the value and walks phases: exit (old content animates out), then after a short delay swap and enter-start (transition off, jump to the start offset), then a double requestAnimationFrame to idle (transition on, animate in). The DOM node is never remounted.

Fix: blocker 6; in useCrossfade, reset to idle when the value returns to what is displayed; drop aria-controls on inactive tabs (their panels do not exist); optimise the screenshots.

DomainRoadmap Minor fixes

How it moves: an IntersectionObserver sets data-active once; CSS fades each card in from above or below (zigzag) with :nth-of-type delays. Hovering a card sends a glowing dot up the nearest divider. Column width is min(241px, (100% − gaps) / 5) and the divider positions are computed from the same variable.

Fix: move the divider <span>s out of the <ol>; give the horizontally scrolling mobile list a scroll affordance.

IdentityOsStatsAndPartners Needs work

How it moves: each logo row is the set repeated (×3 partners, ×6 payments). A gsap.ticker callback moves x by speed × deltaTime (frame rate independent) and adds one set width back when it passes −oneSet, so the loop is seamless. Headers fade up with a one time ScrollTrigger inside gsap.context, reverted on unmount.

Fix: blocker 8; mark repeated copies aria-hidden; pause when off screen; use an <a href="mailto:"> for "Partner With Us".

DomainBlogTeaser Minor fixes

How it works: a horizontal overflow-x: auto row with scroll snap. A callback ref attaches a ResizeObserver; arrows and a progress bar are computed from scrollLeft, scrollWidth and clientWidth. Prev / next scroll by one card width. Cards show a cursor following tooltip using CSS variables.

Fix: remove the duplicate tooltip span in BlogCard.tsx; guard posts without a feature image (empty src); format dates with a fixed time zone to avoid hydration mismatches.

FrequentlyAskedQuestions Minor fixes

How it moves: each item tweens height to 'auto' or 0 with GSAP plus an opacity fade; the caret rotates with CSS. The left column is position: sticky on desktop (the section uses overflow: clip so sticky keeps working).

Fix: hide closed answers from assistive tech (hidden or visibility: hidden after closing); kill running tweens before starting new ones; respect reduced motion; add aria-expanded on View More; consider FAQPage structured data.

Part 4 · Build it yourself: the course

Thirteen modules that take a beginner from an empty Next.js app to this exact landing page. Each module teaches one idea, points at the real file to study, gives the core trick in a few lines, and ends with an exercise. Do them in order: every module reuses what came before.

How to study each module
  1. Read the goal and the concepts.
  2. Build the snippet in a scratch page first, not in the real section.
  3. Open the real file and find the same idea there.
  4. Do the exercise, which usually means fixing one of the audit findings above.
Module 0

Setup and the mental model

Next.js pages routerTypeScriptCSS modulesSCSS

Goal: understand how a page becomes HTML before you write any animation.

  1. Create an app with npx create-next-app@14 --ts and pick the pages router (this project uses pages/, not app/).
  2. Install sass and gsap. Learn that every file in pages/ becomes a route, and pages/_app.tsx wraps every page.
  3. Learn the most important fact for animation work: React renders on the server first. Anything that reads window, document, sizes or the time must run inside useEffect.
  4. Create the folder pattern from Part 2: composites/landing-page/MySection/{index.ts, MySection.tsx, MySection.module.scss}.
// MySection.tsx
import styles from './MySection.module.scss'
export function MySection() {
  return (
    <section className={styles.section} aria-labelledby="my-heading">
      <h2 id="my-heading">Hello</h2>
    </section>
  )
}
export default MySection
Exercise: build an empty page that renders three placeholder sections from a barrel index.ts, exactly like pages/index.tsx does.
Module 1

Design tokens and breakpoints

CSS custom propertiesSCSS mixinsmobile first

Goal: never hardcode a colour or size twice. Study styles/tokens.scss and styles/_mixins.scss.

// tokens.scss  (loaded once, globally)
:root { --color-blue-primary: #2639ed; --space-4: 16px; --text-h1: 65px; }
@media (max-width: 1200px) { :root { --text-h1: 55px; } }   /* token shrinks itself */

// _mixins.scss  (imported into every module)
@mixin tablet-down { @media (max-width: 991px) { @content; } }
@mixin laptop { @media (min-width: 992px) and (max-width: 1279px) { @content; } }

// usage
.title { font-size: var(--text-h1); @include tablet-down { font-size: 30px; } }

Why two systems? Tokens are runtime variables, so they can change in a media query and every component follows. Mixins are compile time shortcuts so breakpoint numbers live in one place.

Exercise: add laptop to the respond-to() mixin, and make the token media queries use the same 767 / 991 limits as the mixins.
Module 2

Part B: the crossfade hook

function useCrossfade<T>(value: T, exitMs = 220) {
  const [display, setDisplay] = useState(value)
  const [phase, setPhase] = useState<'idle' | 'exit' | 'enter-start'>('idle')
  useEffect(() => {
    if (value === display) { setPhase('idle'); return }
    setPhase('exit'); let r1 = 0, r2 = 0
    const t = setTimeout(() => {
      setDisplay(value); setPhase('enter-start')            // transition off, jump to start
      r1 = requestAnimationFrame(() => { r2 = requestAnimationFrame(() => setPhase('idle')) })
    }, exitMs)
    return () => { clearTimeout(t); cancelAnimationFrame(r1); cancelAnimationFrame(r2) }
  }, [value])
  return { display, phase }
}

The double requestAnimationFrame guarantees the browser paints the start position before the transition is switched back on. The setPhase('idle') line in the early return is the fix for the stuck state found in the audit.

The odometer counter

Goal: rebuild DomainOnchainStats. Each digit is a reel: a 1em tall window over a strip 0123456789 written twice.

function Digit({ digit }: { digit: number }) {
  const strip = useRef<HTMLSpanElement>(null)
  const pos = useRef(digit)
  useEffect(() => {
    const el = strip.current!; const prev = pos.current % 10
    if (digit === prev) return
    pos.current += (digit - prev + 10) % 10                 // always roll forward
    el.style.transform = `translateY(-${pos.current * 5}%)` // 20 cells → 5% each
    if (pos.current < 10) return
    const snap = () => { el.style.transition = 'none'; pos.current -= 10
      el.style.transform = `translateY(-${pos.current * 5}%)`
      requestAnimationFrame(() => { el.style.transition = '' }) }
    // the audit bug: with transitions disabled, transitionend never fires
    if (getComputedStyle(el).transitionDuration === '0s') snap()
    else el.addEventListener('transitionend', snap, { once: true })
  }, [digit])
  return <span className="reel"><span ref={strip}>{'01234567890123456789'.split('').map((c, i) => <span key={i}>{c}</span>)}</span></span>
}

const clamp = (v: number) => Math.min(1, Math.max(0, v))
const lerp = (a: number, b: number, t: number) => a + (b - a) * t
function progress(section: HTMLElement) {
  const top = section.getBoundingClientRect().top + scrollY
  return clamp((scrollY - top) / (section.offsetHeight - innerHeight))
}
function cardStyle(p: number, i: number, count = 4) {
  const d = p * (count - 1) - i              // <0 waiting, 0 active, >0 leaving
  if (Math.abs(d) >= 1) return { opacity: 0, scale: 0.8 }
  const t = 1 - Math.abs(d)
  return { opacity: t, scale: lerp(0.75, 1, t) }
}
