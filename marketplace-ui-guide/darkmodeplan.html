Dark Mode Plan

How we bring dark mode to the complete marketplace, based on every dark design in Figma (marketplace akshat): home page, sidebar, My Domains, watchlist, listing flow, buying flow with the domain page and receipt, login and signup, and 404. Planning only, no code has been written.

What changed in this revision

  • Decision: one surface colour, #141415, for every card, table, panel and drawer box on every page, instead of the different opacities in the designs. No per page surface tokens.
  • Every dark design has been read, not just the home page. They all live in the same Figma file, next to their light versions, so no extra links are needed.
  • Added a full work plan in phases, ordered so shared pieces are done once and every phase can ship on its own.
  • Extended the proposed colour scale for the drawers and forms: inputs, selected options, error, warning and success banners, status icons, and charts.
  • Added a list of 11 problems in the Figma file, mostly light mode colours left inside dark frames, for the designer to fix or confirm.
  • The open question "will other pages get dark designs?" is answered. Every main page has one, except older pages like privacy policy and the watchlist card view.

Work plan

How the phases are ordered. First a foundation that changes nothing visually, then the parts every page shares (shell and primitives), then one page area per phase. Each phase is a separate PR that's safe to merge, because the theme toggle stays hidden behind a flag until the final phase. Light mode must look pixel identical after every phase.

What the dark designs tell us

Black and white with opacity

Confirmed by the designer: no Figma variables. We define the scale ourselves and the designer approves it.

True black base, mixed surfaces

Pages and drawers are pure #000000. Cards, tables and panels use about seven different backgrounds across pages (solid near blacks and white at 5% or 9%). We're unifying them into one surface.

Far too many text levels

Across all pages, text uses white at over 20 different opacities, from 23% to 88%. They group naturally into four levels.

Selected states invert or glow

Active tabs, chips, Quick sale and the toggle are white with black text. Selected option cards in drawers use a black to #333 gradient with a white border.

Status colours vary a lot

Eight different greens, four reds, an amber warning, and three purples for charts and links. These need to be cut down to one per meaning.

Drawers share one pattern

Black body, header with a divider, a footer with a soft white glow above it, and a wide primary button. Building this once covers both listing and buying flows.

Status icons are glowing badges

Success is a green gradient circle, failure red, pending blue, and warnings a red tinted circle. These are probably worth one shared primitive.

Login keeps light buttons

The Google and wallet login buttons stay light (#f3f3fe and white with #282828 text) on the black page. This needs confirming as intentional.

Assets need dark versions

The home hero, login illustration panel, white text logo and the noise tile. The 404 illustration appears to be the same in both.

Toggle is desktop only

The sun and moon pill appears in desktop headers on every page, but on no mobile or iPad frame.

Proposed dark scale

One surface everywhere. The designs use about seven different card and panel backgrounds across pages. We deliberately replace all of them with a single solid surface, #141415, on a pure black page. Every card, table, panel and drawer box looks the same on every page, which keeps the dark theme calm and consistent. When a card sits inside a panel, a white 10% border separates them instead of a second shade. Only text and borders use white at an opacity, so they blend naturally with whatever they sit on.

How light and dark images swap

For the few images that need a dark version, render both and let CSS show the right one based on the theme attribute on html (for example, hide the light one under the dark theme). Because the inline script sets that attribute before the first paint, the correct image shows immediately. Choosing the image in JavaScript instead would show the light image for a moment, then swap, which is the flash we're trying to avoid. CSS background images (like the hero) simply get a second rule under the dark theme.

Rules going forward

  • Monochrome UI icons are inline components or react-icons using currentColor, never black or gray SVG files.
  • An SVG file is only for multicolour artwork, logos and illustrations.
  • Every new image is checked on both a white and a black background before it's added.

Reading colours from Figma

  • All colours in a frame: select the frame and check "Selection colors" in the right panel. It lists every colour with hex and opacity, and clicking one shows which layers use it.
  • One element: turn on Dev Mode (Shift D), click a layer, and read its fill, border and opacity in the Inspect panel.
  • Variables: this file has none, confirmed by the designer, so the token scale is defined by us.
  • Through Claude: the Figma connection reads every colour in a frame from its node ID. That's how the tables and issues above were built.
