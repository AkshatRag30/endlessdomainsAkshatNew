Phase 12

Font loading audit + fix

real bug2 files
Files
pages/_document.tsx, design-system/styles/fonts.scss
Figma nodes
1:1016, 1:1041, 1:1124, 1:1091, 1:1859, 1:1912, 1:1854 — spot-checked live font family/weight/size/color across a heading, a table cell, a column header, and sidebar nav labels

Raised by you as "the font weight looks thin against Figma." Traced it to a real bug, not a sizing mismatch: fonts.scss's own comment claimed Satoshi and Space Grotesk were loaded as <link> tags in _document.tsx, but that file had no such tags, and a repo-wide search turned up no @font-face, no local woff files, and no next/font usage anywhere. Every element requesting either font was silently falling back to the browser's default sans-serif at whatever weight was requested — that's what read as "thin," since Satoshi's real letterforms are noticeably bolder than a fallback face at the same weight. Fixed by adding real <link> tags: Fontshare's CDN for Satoshi, Google Fonts for Space Grotesk. Satoshi specifically uses Fontshare's @variable request (300–900 in one continuous face) rather than fixed weights, since Fontshare's static build has no 600/semibold instance and this codebase already sets Satoshi to semibold in two places — fixed weights would have silently substituted the nearest static weight instead of rendering the real one. While auditing this, also found and flagged (not fixed, a separate decision) that SidebarSection/SidebarPromoCard use Satoshi semibold where the live BROWSE label in Figma is actually Satoshi medium — left as-is pending your call.

Verified: curled both font CSS endpoints directly and confirmed the returned font-family names and weight coverage; confirmed the live dev server's rendered HTML included the corrected link tags.

Two unrelated auth-state bugs, both raised by you as questions rather than bug reports. One: SidebarPromoCard's CTA is the exact same "connect wallet" action, pointed at the exact same /login destination, as Header's own connect-wallet button — but Header already hides that button once authenticated is true, while the promo card had no auth check at all and would keep prompting an already-connected user to connect. Verified: clean compile after each fix; confirmed the route guard change follows the exact existing exception pattern rather than a new one.

04

How easy would real API integration be

The swap boundary designed in from Phase 2: every composite receives typed data as props or reads it from a small hook, never an RTK Query hook directly. Swapping mock data for a real endpoint means changing the inside of one hook plus a small mapper function — no composite or primitive touched. That part is done and true today. What varies a lot is whether the backend actually has the endpoint to call yet.

DataBackend todayWhat's neededEffort
Live Listings table
MarketplaceListing[]		 Real endpoint already exists and is already used elsewhere in the app (useGetAllDomainListingByQueryQuery) Write one mapper function reshaping DomainListing → MarketplaceListing, swap the hook's internals Easy

MarketplaceListing[] (filtered)		 Real endpoint already exists (useGetPromotedDomainQuery), currently unused by the archived page too Same mapper as above, reused Easy
Category tab counts
ListingCategory[]		 No dedicated endpoint; counts would need computing from listing data or a small new aggregate Either a small new backend aggregate, or compute client-side from a full listing fetch Medium
Sidebar account counts
Watchlist, My domains, etc.		 Watchlist and My Domains are real, already-linked pages backed by real per-user endpoints; the counts themselves aren't fetched yet Wire the existing per-user hooks (already used on those real pages) into the sidebar data Medium
Live Activity feed
ActivityFeedItem[]		 Confirmed during planning: no market-wide activity feed endpoint exists anywhere in the backend, only a per-user history endpoint Needs new backend work first — a real-time or polled market-wide event feed doesn't exist to call yet Hard, backend-blocked

Net read: the left two-thirds of the page, listings, promoted cards, filtering, is close, the real endpoints already exist and are already used elsewhere in this codebase. The right rail, Live Activity and Market Activity, is the part that's genuinely blocked on new backend work, not frontend effort, since those endpoints simply don't exist yet.

05

Known gaps, said plainly

  • Two background noise textures from the Figma file, behind the header's search box and behind both right-rail panels, were skipped rather than downloaded as a second raster asset for a barely-visible 5% opacity effect.
  • The hero's blurred gradient bar above Promoted Domains is approximated with a CSS blur, not the exact exported image.
  • Chain logos are colored dots, not real per-chain icons — no such assets exist in the project for Polygon, Ethereum, Arbitrum, or BNB Chain.
  • The sidebar's collapse-to-icons chevron and its "Explore" toggle switch are not built — neither has a defined behavior or the icon assets they'd need.
  • Every "Buy Now" and every favorite heart is real and clickable but wired to nothing — no BuyNowModal, no wallet call, exactly as required for this phase of the work.
  • Responsive behavior (Phases 11 and 14) was verified by compiling and reading the CSS/breakpoints carefully against real Figma screenshots, not by looking at an actual rendered narrow or tablet-width viewport — this project has no browser automation tool installed.
  • Figma's mobile mockup shows two icon-chip buttons (message, search) in the header where the tablet mockup instead shows the real connect-wallet button — since neither icon's behavior was ever specified, the header keeps its real, functioning connect-wallet/account slot at every width instead of building non-functional icons to match the screenshot exactly.
  • There's no Figma reference for what the mobile drawer looks like in its open state — it still uses the plain white panel styling built back in Phase 4, not a design-matched version.
  • The /design-preview allowlist added to ProtectedRoute in Phase 15 is a temporary carve-out tied to this being a temporary route — it should come out once Phase 16 integration replaces it with the real page at its real URL.

Where things stand

Phases 2 through 15 are built, verified, and live on the temporary preview route /design-preview/marketplace, which is not linked from anywhere in the real app and, as of Phase 15, is reachable whether or not you're logged in. Phases 12 through 15 were a QA and fidelity pass on top of the original 2–11 build — a real font-loading bug, two small Figma corrections, a full mobile/tablet responsive rebuild against real device mockups, and two auth-state bugs — not new features. Phase 16, wiring all of this into the real pages/index.tsx and retiring the temporary Login/Sign Up page, is intentionally on hold right now while visual mismatches against the Figma reference get fixed first, at your request. Nothing in this document has been wired into the live site yet.
